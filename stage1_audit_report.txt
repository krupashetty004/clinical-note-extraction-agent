## Quick Start (Local)

### Prerequisites

- Python 3.12+
- Windows / macOS / Linux

### 1. Clone and enter the project

```bash
cd clinical-note-extraction-agent
```

### 2. Create and activate a virtual environment

```bash
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
# macOS / Linux
source .venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Apply database migrations and seed roles

```bash
python manage.py migrate
```

This creates an SQLite database at `db.sqlite3` and seeds the `Doctor` and `Admin` workspace roles.

### 5. Create a superuser (admin account)

```bash
python manage.py createsuperuser
```

Follow the prompts to set a username and password.

### 6. Add the superuser to the Doctor group

```bash
python manage.py shell -c "
from django.contrib.auth import get_user_model
from django.contrib.auth.models import Group
u = get_user_model().objects.get(username='<your-username>')
u.groups.add(Group.objects.get(name='Doctor'))
print('Done')
"
```

Replace `<your-username>` with the username you created above.

### 7. Start the development server

```bash
python manage.py runserver
```

Open **http://127.0.0.1:8000/** in your browser and sign in.

## Demo Workflow

### Create a patient and encounter

1. Log in at http://127.0.0.1:8000/
2. Go to **Patients â†’ New Patient**
3. Create a **Patient**, then an **Encounter**, then add a **Clinical Note**

### Run AI extraction on a note

On the patient detail page, click **"Process with AI Agent"** (POST to `/notes/<id>/process/`).

- If a Groq API key is configured in Settings and `GROQ_PROVIDER_ENABLED=True`, the Groq extraction provider is used.
- Otherwise the **local offline extraction engine** (`LocalClinicalExtractionProvider`) runs â€” no network call required.

The run is saved and you are redirected to the processing run detail page.

### Review and export

1. On the processing run detail page, review extracted items.
2. Click **Approve** or **Reject** to complete review.
3. Click **"Export reviewed JSON"** to download the structured result as a JSON attachment.

### Optional: Run the synthetic demo

To use the built-in synthetic data demo (no real notes needed), set `SYNTHETIC_DEMO_ENABLED=True` in your environment or `config/settings.py`, then click **"Run synthetic demo"** on any patient detail page.

# Revised System Architecture, Technology Stack, and Hosted Workflow

**Project:** AI-Powered Clinical Note Extraction and Coding Agent  
**Revision:** 16 October 2026  
**Status:** Proposed design; expanded requirements, hosting, provider, and data handling pending formal Mirai Labs approval.

> The revised doctor workspace is materially broader than the original SOW. Use synthetic data for public-hosting and UI tests. Do not upload Mirai Labs clinical notes or enable external model processing until the exact scope, provider, hosting, storage, and data-handling arrangements are approved in writing.

## 1. Product Direction

The application is designed around the doctor's workflow rather than around individual AI tasks. A doctor signs in, sees authorized patients and recent activity, opens a patient record, reviews current and previous encounters, processes a clinical note, inspects evidence-linked results, manages reference knowledge, and configures/tests the active AI provider/model from a central settings page.

### Doctor-facing navigation

1. **Dashboard:** recent activity, pending review items, recent patients, and useful actions.
2. **My Patients:** searchable list of authorized patients.
3. **Patient Record:** overview, current encounter, prior encounters, clinical notes, diagnosis mentions, medication mentions, allergies, measurements, procedure mentions, and review history.
4. **Clinical Notes / Review:** submit or open a note, inspect extracted items and evidence, accept/reject/flag items, inspect ICD-10 candidates, and export reviewed JSON.
5. **Knowledge Base:** add text, text files, multi-page PDFs, images, and voice/audio; preview/correct extracted content; edit, tag, prioritise, publish, version, deactivate, and re-index knowledge.
6. **Activity / History:** inspect processing runs, review actions, configuration changes, and safe operational events.
7. **AI Settings:** one central place to configure the active provider/model and supported parameters, test connectivity with synthetic input, and activate the saved configuration.
8. **Administration:** manage users and role assignment; restrict to administrators where appropriate.

Do not hardcode patient names, knowledge records, model names, dashboard counters, or uploaded-file lists. Populate these views from persisted data.

## 2. Original SOW vs Expanded Proposal

The original SOW requires extraction, original-source evidence/offsets, diagnosis-code candidates from the supplied ICD-10 table, independent verification, bounded orchestration, safe traces, human review, and quantitative evaluation. Its baseline scope is local/one reviewer/text notes; OCR and cloud/multi-user deployment were excluded.

The expanded proposal adds a hosted doctor workspace, user roles, patient/encounter history, an editable multimodal knowledge base, RAG, model configuration through the UI, cloud database/storage, and a hosted public demo. These are scope changes, not assumed SOW requirements. Obtain written Mirai Labs approval before implementing them against project data. Use synthetic data while approval is pending.

## 4. Data Sources Must Stay Distinct

The system has three logically different sources:

1. **Original clinical note:** the evidence source for each extracted claim. Accepted entity evidence and character offsets must point into this original text.
2. **Supplied ICD-10 reference table:** the canonical source for diagnosis-code candidates and code descriptions. Do not invent codes. Procedure-code assignment remains out of scope.
3. **Doctor-managed reference knowledge / patient history:** RAG may retrieve approved reference passages and relevant history for context, but their sources must remain identified and access-filtered. A knowledge-base document is not proof that a diagnosis was written in the current clinical note.

Patient history retrieval must be scoped to the current authorised patient. A query for one patient must never retrieve another patient's notes, encounter content, or identifiers. Reference knowledge and patient-specific history should use separate retrieval scopes or mandatory metadata filters.

## 5. Main Doctor Workflow

### 5.1 Login and dashboard
- Authenticate each user before loading patient, note, knowledge, or AI-settings data.
- Enforce permissions in Django views/services and database queries; hiding a button is not authorization.
- The proposed initial roles are Doctor and Administrator. The Doctor role manages authorized patients/encounters, knowledge records, review decisions, andâ€”if approvedâ€”central AI settings. Administrators manage account/role administration and system-wide settings.
- Create synthetic demonstration users and records; never put passwords, real patient data, provider keys, or uploaded clinical files in GitHub.

### 5.2 Patients and encounters
- Search only patients the logged-in doctor is permitted to access.
- Separate a patient's current encounter from previous encounters.
- Keep notes, processing runs, accepted/rejected items, model version identifiers, and review decisions attached to a specific encounter.
- Preserve history instead of silently overwriting a previous extraction.
- Label historical diagnoses and medication mentions with their date/context; do not promote historical mentions to current facts without support in the present note.

### 5.3 Clinical-note extraction
1. Receive an English text note for the approved encounter workflow.
2. Preserve the exact original note as immutable evidence source.
3. Perform local identifier masking before any approved external model call; maintain an explicit map between masked and original character positions.
4. Call the active model configuration using the extraction prompt and strict output contract.
5. Validate the response using Pydantic and additional checks for offsets/evidence; schema validity alone is not correctness.
6. Retrieve diagnosis-code candidates from the supplied code table using keyword and semantic search. Return no-confident-match when unsupported.
7. Run an independent verification pass using the note and proposed items, not the extractor's hidden reasoning.
8. Reconcile outcomes in an explicit Python agent loop. Retry only recoverable failures within a configured call/time budget.
9. Accept only items passing evidence, status, offset, and verification checks; reject unsupported claims, abstain if coding is uncertain, and route unresolved cases to item review or note escalation.
10. Show the original note with evidence highlighting, status, code candidates, flags/reasons, trace-safe process history, and accept/reject controls.
11. Persist review results and export reviewed JSON.

The central settings page normally selects one active provider/model for the application. The same selected model can be invoked with different extraction and verification instructions in separate passes. A distinct verifier model is an optional advanced decision; do not make the doctor configure every task separately unless Mirai Labs specifically asks for it.

### 5.4 Multimodal reference knowledge ingestion
1. Doctor enters text or uploads a supported text file, PDF, image, or audio file.
2. Validate extension, MIME type, actual content, size, and limits; reject unsupported or unsafe files.
3. Store the original object in a private bucket and create a database record with owner, source, status, version, timestamps, category, tags, and priority.
4. Text files are parsed directly. PDFs are parsed page-by-page for selectable text using pypdf; only pages with little/no selectable text are rendered using pdf2image + Poppler and passed to Tesseract OCR. Images use Tesseract OCR. Audio uses a tested local CPU speech-to-text option or an approved free-tier service; it must never silently invoke a paid provider.
5. Show extracted text/transcription for doctor correction and confirmation before publication.
6. Split approved text into traceable chunks; create vectors with a local embedding model; store chunks, vectors, source references, and metadata in PostgreSQL/pgvector.
7. On edit/deactivation, mark old versions and ensure stale chunks are updated or removed from retrieval. Re-indexing failures must be visible.
8. Record source attribution in retrieval results so the doctor can inspect what informed the generated output. For PDF sources, retain the original file reference and page number(s) for each extracted chunk where available.

PDFs, images, and voice are inputs to the **knowledge base** in this expanded scope, not a claim that the original SOW's clinical-note input is now unrestricted multimodal. PDF knowledge ingestion does not automatically change the original SOW exclusion of scanned clinical-note input.

### 5.5 RAG and priority logic
- Retrieve candidates using keyword/full-text matching and vector similarity.
- Apply mandatory permissions and scope filters first; then relevance thresholding, ranking, and optional doctor-configured priority.
- Priority should influence ordering among relevant eligible results; it must not make unrelated or unsafe text outrank better evidence solely because it has a high priority.
- Deduplicate overlapping chunks and keep document title, version, source, and chunk reference.
- Pass only the relevant, approved context to the model.
- Separate reference-knowledge citations from clinical-note evidence offsets; every accepted extracted claim still needs original-note evidence.

A starting ranking can be evaluated as a normalized blend of semantic similarity, lexical relevance, and a small bounded priority adjustment. The weights and threshold must be validated on labelled examples rather than assumed correct.

### 5.6 Central AI Settings
- One settings page selects the approved provider/model and supported generation parameters for the whole application.
- Provide Test Connection, Show Test Result, Save Draft, and Activate actions.
- Test only with synthetic/non-sensitive input. Check connectivity, model availability, response status, schema output when required, latency, and errors.
- Restrict provider options/endpoints to a documented allowlist. Arbitrary URLs are not accepted.
- Mask API keys in the UI. Store credentials encrypted using an application encryption key kept in deployment environment secrets; never log keys.
- Record configuration ID/version, who changed it, time, provider/model identifier, and test result. Never log the secret.
- A successful connectivity test does not prove clinical accuracy or data-policy approval.
- On invalid key, unsupported model, or quota exhaustion, preserve current active config unless the user explicitly confirms a tested new one. Do not switch providers silently.

### Why Neon instead of Supabase?
Neon is a PostgreSQL hosting provider, not an alternative database engine. Both Neon and Supabase provide hosted PostgreSQL; the architecture chooses Neon for the database and pgvector. It does not rely on Supabase's application authentication because Django handles login and role permissions. Neon Object Storage is the preferred bundled file-storage choice; current official documentation marks it generally available and lists 5 GB per project on the Free plan. Its private access, quota, and integration still need an implementation test. Supabase Storage Free remains a fallback if Neon Object Storage does not meet those conditions. Avoid deploying both storage systems unless there is a demonstrated need.

### Free-tier constraints
- Current Neon Free limits checked on 16 October 2026 include 1 GB PostgreSQL storage/project, 100 CU-hours/project/month, 5 GB public network transfer/project/month, and 5 GB Object Storage/project. Recheck quotas before deployment.
- Current Supabase Free documentation lists 500 MB database size, 1 GB storage, and 5 GB egress; projects can be paused under free-plan rules.
- Render Free web services can sleep and use ephemeral local storage; do not treat the application filesystem as persistent.
- AI APIs, OCR, and transcription must respect free quotas and input limits. The system must explain/defer on quota exhaustion and must not trigger paid fallback.
- Keep synthetic demo data and monitor limits. Free tiers are suitable for a bounded evaluation demo, not a promise of unlimited or production-grade availability.

## 7. Main Data Model (Logical Proposal)

- **User / DoctorProfile:** Django user ID, role/group, active status, profile metadata.
- **Patient:** non-hardcoded patient record with internal ID and minimum necessary fields.
- **PatientAccess:** relationship describing which doctors can access each patient, unless a simpler documented practice-wide permission model is approved.
- **Encounter:** patient ID, encounter date, status, creating doctor, and links to encounter notes.
- **ClinicalNote:** encounter ID, original text, note version/source, author, timestamps. Store only approved data; public demo records must be synthetic.
- **ExtractionRun:** note/version ID, config-version ID, model identifier, status, latency, call count, safe trace reference.
- **ExtractedItem:** type, entity, attributes, status, evidence text, original offsets, code candidates, verification result, reviewer decision.
- **KnowledgeDocument:** owner, storage key, source filename, source type, title, category, tags, priority, status, version, extracted text, review/publication state.
- **KnowledgeChunk:** document/version ID, chunk index/text, embedding vector, searchable text, metadata and source reference.
- **ICDCode:** code, description and any supplied metadata from the approved canonical table; do not invent or externally substitute codes.
- **AIConfiguration:** provider/model identifier, supported parameters, encrypted credential reference, active/test status, version and updated-by metadata. Never store API keys as plaintext.
- **ReviewAction / AuditEvent:** who did what and when, entity/config identifiers, and safe result metadata.

This is a proposed schema. Final fields, indexes, retention, and access controls must be tested and approved.

## 8. Security and Reliability Controls

- Enforce authentication and permissions server-side for every patient, encounter, note, document, export, and configuration endpoint.
- Test horizontal access control: Doctor A must not retrieve Doctor B's patient records unless explicitly authorised.
- Keep knowledge-source retrieval and patient-history retrieval logically separate and scoped.
- Validate uploads for type, size, content and PDF page count; limit PDF rendering/OCR work and processing time; store files privately. Do not use public object URLs for sensitive files.
- Use short-lived signed file URLs if needed and verify the ownership/access decision before generating a link.
- Avoid remote image/audio parsers that execute untrusted content. Use controlled subprocesses and timeouts for local OCR/transcription.
- Keep original note text authoritative for offsets; test masking-to-original mapping, including repeated text occurrences.
- Treat clinical note and uploaded knowledge text as untrusted input; document text must not override system instructions or provider policies.
- Limit retries, time, file size, PDF page count, rendered-page DPI, model call counts, token/audio duration, and ingestion jobs.
- Ensure logs do not contain secrets, API keys, private file URLs, or protected note content.
- Store secrets in deployment environment variables; use a separate encryption key for any credential encrypted at rest in the settings table.
- For the free demo, use synthetic data. Do not claim clinical safety, regulatory compliance, or production readiness.

## 5. Clinical Note Extraction Logic

1. Receive the selected encounter's note through the approved workflow.
2. Preserve the original string immutably; use it as the source for validation and highlights.
3. Detect/mask identifiers locally before an approved external model request. Save a tested map from transformed-text offsets back to original-note offsets.
4. Call the active model using an explicit extraction prompt and a strict output schema.
5. Validate schema fields with Pydantic, then separately validate span bounds, exact evidence text and original-offset mapping.
6. Extract the required categories: diagnosis mentions/status, medication name/dose/route/frequency/status where stated, procedures/status, allergies, and vitals/measurements/units where stated.
7. Retrieve diagnosis-code candidates from the supplied ICD-10 table. Use PostgreSQL full-text/keyword retrieval and a pgvector semantic path if it demonstrates value. Do not assign procedure codes.
8. Pass the note and proposed structured items to an independent verification call without supplying the extractor's hidden reasoning.
9. Check evidence support, offsets, current/absent/uncertain/historical status, contradiction signals, and likely omissions.
10. The explicit orchestrator reconciles results. Accept only items passing the agreed gates; reject unsupported results, abstain on weak code matches, retry only recoverable failures within the budget, and flag unresolved items.
11. Persist the original note, structured output, run/model configuration identifier, review decision and safe process metadata under the correct encounter.
12. Present output with highlighted evidence and export reviewed JSON.

A valid JSON object can still contain fabricated or unsupported information; schema validation, evidence validation, semantic verification, and clinical review are distinct controls.

## 6. Knowledge Ingestion and RAG

### Ingestion
1. Doctor enters text or uploads supported text, image, or audio.
2. Validate file type/content/size and reject unsupported or unsafe content.
3. Store the original uploaded object privately. Create a metadata record with owner, source, type, status, version, category, tags and priority.
4. Parse selectable PDF text page by page with pypdf. For pages with little/no selectable text, render only those pages to images using pdf2image + Poppler and run Tesseract OCR. OCR images and transcribe audio using a tested local component or an approved free-tier API.
5. Show extracted text/transcription to the doctor for correction and approval before publication.
6. Chunk the approved text. Generate embeddings using a local sentence-transformer model and store vectors/chunk metadata in pgvector.
7. Keep document version and chunk lineage, and update/remove stale vectors when the document is edited or deactivated.
8. Keep PDF page numbers in source metadata, enforce PDF page/file-size limits and timeouts, and surface parsing/OCR/transcription/embedding failures; never publish incomplete content silently.

### Retrieval
- Enforce user permissions, document status, tenant/patient scope and other metadata filters before ranking.
- Search keywords/full text and vector similarity, deduplicate, combine/rank results and return source citations.
- Allow the doctor to set priority for a knowledge record/category/source. Treat priority as a bounded ranking input among eligible relevant documents, not a substitute for relevance or clinical evidence.
- Apply a relevance threshold and provide a no-relevant-context outcome when appropriate.
- Reference knowledge, patient history, and current note evidence must remain clearly identifiable and separately scoped.
- Use the original note as proof for an extracted entity; reference knowledge can provide context, not claim presence in the note.
- Adding knowledge updates the index; it does not train or fine-tune the LLM.

"""Persistence boundary for clinical-note processing runs.

Coordinates the orchestrator with Django persistence.
Providers must be supplied explicitly by the caller.

The caller must authorize access to the note before invoking this service.
No external AI provider is configured automatically.
"""

import logging

from django.utils import timezone

from dashboard.extraction.orchestrator import (
    VerificationProvider,
    run_agent_workflow,
)
from dashboard.extraction.pipeline import ExtractionProvider
from dashboard.models import ClinicalNote, ClinicalProcessingRun

logger = logging.getLogger(__name__)


def process_clinical_note(
    note: ClinicalNote,
    initiated_by,
    *,
    extraction_provider: ExtractionProvider,
    verification_provider: VerificationProvider,
    max_extraction_attempts: int = 2,
    max_verification_attempts: int = 2,
    execution_mode: str = ClinicalProcessingRun.ExecutionMode.UNKNOWN,
) -> ClinicalProcessingRun:
    """Create, execute, and persist one processing run.

    Each invocation creates a separate run. The original clinical note
    is never modified.

    The caller is responsible for authorization and supplying explicitly
    configured provider implementations.
    """
    if not isinstance(note, ClinicalNote):
        raise TypeError("note must be a ClinicalNote instance.")

    if note.pk is None:
        raise ValueError("Save the clinical note before processing it.")

    if not getattr(initiated_by, "is_authenticated", False):
        raise PermissionError(
            "An authenticated user is required to process a note."
        )

    if execution_mode not in ClinicalProcessingRun.ExecutionMode.values:
        raise ValueError("execution_mode must be a supported processing mode.")

    run = ClinicalProcessingRun.objects.create(
        clinical_note=note,
        created_by=initiated_by,
        status=ClinicalProcessingRun.Status.PENDING,
        execution_mode=execution_mode,
    )

    run.status = ClinicalProcessingRun.Status.RUNNING
    run.started_at = timezone.now()
    run.save(update_fields=["status", "started_at"])

    try:
        result = run_agent_workflow(
            extraction_provider,
            verification_provider,
            note.original_text,
            max_extraction_attempts=max_extraction_attempts,
            max_verification_attempts=max_verification_attempts,
        )
    except Exception as exc:
        # Log only the exception class, never its message or clinical text.
        logger.error(
            "Clinical processing failed (exception_type=%s).",
            type(exc).__name__,
        )

        # Do not persist exception details because they could contain
        # sensitive note content, credentials, or provider information.
        run.status = ClinicalProcessingRun.Status.FAILED
        run.failure_code = "processing_service_failed"
        run.review_reasons = [
            "Processing failed unexpectedly; manual review is required."
        ]
        run.finished_at = timezone.now()

        run.save(
            update_fields=[
                "status",
                "failure_code",
                "review_reasons",
                "finished_at",
            ]
        )
        return run

    # Persist the attempt counts and structured outputs.
    run.extraction_attempts = result.extraction_attempts
    run.verification_attempts = result.verification_attempts

    run.extraction_result = (
        result.extraction.model_dump(mode="json")
        if result.extraction is not None
        else None
    )

    run.coding_result = (
        result.coding.model_dump(mode="json")
        if result.coding is not None
        else None
    )

    run.verification_result = (
        result.verification.model_dump(mode="json")
        if result.verification is not None
        else None
    )

    run.item_dispositions = [
        disposition.model_dump(mode="json")
        for disposition in result.item_dispositions
    ]

    run.review_reasons = list(result.review_reasons)
    run.failure_code = result.failure_code or ""

    status_mapping = {
        "completed": ClinicalProcessingRun.Status.COMPLETED,
        "needs_review": ClinicalProcessingRun.Status.NEEDS_REVIEW,
        "failed": ClinicalProcessingRun.Status.FAILED,
    }

    run.status = status_mapping[result.status]
    run.finished_at = timezone.now()

    run.save(
        update_fields=[
            "status",
            "extraction_attempts",
            "verification_attempts",
            "extraction_result",
            "coding_result",
            "verification_result",
            "item_dispositions",
            "review_reasons",
            "failure_code",
            "finished_at",
        ]
    )

    return run


__all__ = ["process_clinical_note"]

class LocalClinicalExtractionProvider:
    """Extract clinical entities strictly grounded in the original source note."""

    def extract(self, input_text: str) -> dict[str, Any]:
        if not isinstance(input_text, str):
            raise TypeError("input_text must be a string.")

        text_lower = input_text.lower()
        items: list[dict[str, Any]] = []
        occupied_spans: list[tuple[int, int]] = []

        def overlaps(s: int, e: int) -> bool:
            return any(max(s, os) < min(e, oe) for os, oe in occupied_spans)

        category_map = {
            "diagnoses": "diagnosis",
            "medications": "medication",
            "procedures": "procedure",
            "allergies": "allergy",
            "vital_signs": "vital_sign",
        }

        for group_key, terms in CLINICAL_TERMS.items():
            category = category_map[group_key]
            for term in sorted(terms, key=len, reverse=True):
                cursor = 0
                while True:
                    idx = text_lower.find(term, cursor)
                    if idx == -1:
                        break
                    end = idx + len(term)
                    cursor = end

                    prev_char = text_lower[idx - 1] if idx > 0 else " "
                    next_char = text_lower[end] if end < len(text_lower) else " "
                    if prev_char.isalnum() or next_char.isalnum():
                        continue

                    if overlaps(idx, end):
                        continue

                    evidence = input_text[idx:end]
                    status = None
                    if category == "diagnosis":
                        window = text_lower[max(0, idx - 40):idx]
                        if any(w in window for w in ["history of", "hx of", "past history", "prior"]):
                            status = "historical"
                        elif any(w in window for w in ["no evidence of", "ruled out", "negative for", "denies"]):
                            status = "ruled_out"
                        elif any(w in window for w in ["possible", "probable", "rule out", "suspected", "question of"]):
                            status = "suspected"
                        else:
                            status = "active"

                    elif category == "medication":
                        window = text_lower[max(0, idx - 40):idx]
                        if any(w in window for w in ["discontinued", "stopped", "off", "d/c"]):
                            status = "discontinued"
                        elif any(w in window for w in ["started on", "prescribed", "begin", "newly"]):
                            status = "newly_prescribed"
                        else:
                            status = "current"

                    items.append({
                        "category": category,
                        "entity": evidence,
                        "evidence_text": evidence,
                        "start_offset": idx,
                        "end_offset": end,
                        "status": status,
                        "attributes": {},
                    })
                    occupied_spans.append((idx, end))

        # Sort by start offset
        items.sort(key=lambda x: x["start_offset"])

        return {
            "items": items,
            "needs_review": False,
            "review_reasons": [],
        }


class LocalClinicalVerificationProvider:
    """Verify evidence integrity, offsets, contradictions, and status.

    Returns a payload conforming to the VerificationResult schema expected
    by the orchestrator's validate_verification_output() contract:
    each item_check must include item_index, outcome, status_check, reason,
    and evidence fields.
    """

    # Categories that carry a status field in the extraction contract.
    _STATUS_CATEGORIES = {"diagnosis", "medication"}

    def verify(
        self,
        original_note: str,
        extraction: ExtractionResult,
        coding: DiagnosisCodingBatch,
    ) -> dict[str, Any]:
        if not isinstance(original_note, str):
            raise TypeError("original_note must be a string.")

        item_checks: list[dict[str, Any]] = []
        needs_review = False
        review_reasons: list[str] = []

        for index, item in enumerate(extraction.items):
            start = item.start_offset
            end = item.end_offset
            evidence = item.evidence_text
            status_applies = item.category in self._STATUS_CATEGORIES

            # Check offset and evidence validity
            if (
                start < 0
                or end > len(original_note)
                or end <= start
                or original_note[start:end] != evidence
            ):
                item_checks.append({
                    "item_index": index,
                    "outcome": "unsupported",
                    "status_check": "correct" if status_applies else "not_applicable",
                    "reason": "Evidence text does not match original note at specified character offsets.",
                    "evidence": [],
                })
                needs_review = True
                review_reasons.append(f"Item #{index} offset mismatch.")
                continue

            # Check grounding of entity tokens in evidence
            if not _tokens(item.entity).issubset(_tokens(evidence)):
                item_checks.append({
                    "item_index": index,
                    "outcome": "unsupported",
                    "status_check": "correct" if status_applies else "not_applicable",
                    "reason": "Entity is not grounded in the quoted evidence text.",
                    "evidence": [],
                })
                needs_review = True
                review_reasons.append(f"Item #{index} entity ungrounded in evidence.")
                continue

            # Build evidence reference for supported items
            evidence_ref = {
                "evidence_text": evidence,
                "start_offset": start,
                "end_offset": end,
            }

            # Determine status_check for diagnoses and medications
            if status_applies:
                status_check = "correct"
                # Check for contextual contradictions in a short window before the span
                window = original_note[max(0, start - 60): start].lower()
                if item.category == "diagnosis":
                    if item.status == "active" and any(
                        w in window
                        for w in ["no evidence of", "ruled out", "negative for", "denies", "not"]
                    ):
                        status_check = "uncertain"
                        review_reasons.append(f"Item #{index} active status may conflict with negation context.")
                    elif item.status == "historical" and any(
                        w in window for w in ["history of", "hx of", "past", "prior"]
                    ):
                        status_check = "correct"
                    elif item.status == "ruled_out" and not any(
                        w in window
                        for w in ["no evidence of", "ruled out", "negative for", "denies", "not"]
                    ):
                        status_check = "uncertain"
                    elif item.status == "suspected" and not any(
                        w in window
                        for w in ["possible", "probable", "suspected", "question of", "rule out"]
                    ):
                        status_check = "uncertain"
                elif item.category == "medication":
                    if item.status == "discontinued" and not any(
                        w in window for w in ["discontinued", "stopped", "off", "d/c"]
                    ):
                        status_check = "uncertain"
            else:
                status_check = "not_applicable"

            item_checks.append({
                "item_index": index,
                "outcome": "supported",
                "status_check": status_check,
                "reason": "Evidence directly supports the extracted entity in the original note.",
                "evidence": [evidence_ref],
            })

            if status_check in {"incorrect", "uncertain"}:
                needs_review = True

        if needs_review and not review_reasons:
            review_reasons.append("One or more items require clinical review.")

        return {
            "item_checks": item_checks,
            "potential_omissions": [],
            "needs_review": needs_review,
            "review_reasons": review_reasons,
        }

"""Validation contract for independent clinical extraction verification.

This module validates a verifier's structured output. It does not call an
AI provider or determine clinical truth on its own.
"""

from typing import Annotated, Literal

from pydantic import (
    BaseModel,
    ConfigDict,
    Field,
    StrictBool,
    StrictInt,
    StrictStr,
    ValidationError,
    model_validator,
)

from dashboard.extraction.schema import (
    EntityCategory,
    ExtractionResult,
    entity_evidence_is_grounded,
    validate_item_status_context,
    validate_evidence_spans,
)


VerificationOutcome = Literal[
    "supported",
    "unsupported",
    "contradicted",
    "uncertain",
]

StatusCheck = Literal[
    "correct",
    "incorrect",
    "uncertain",
    "not_applicable",
]


class EvidenceReference(BaseModel):
    """A quoted source span used by the verifier."""

    model_config = ConfigDict(extra="forbid", frozen=True)

    evidence_text: StrictStr = Field(min_length=1)
    start_offset: Annotated[StrictInt, Field(ge=0)]
    end_offset: Annotated[StrictInt, Field(gt=0)]

    @model_validator(mode="after")
    def validate_span(self) -> "EvidenceReference":
        if not self.evidence_text.strip():
            raise ValueError("Evidence text must not be blank.")

        if self.end_offset <= self.start_offset:
            raise ValueError(
                "end_offset must be greater than start_offset."
            )

        return self


class ItemVerification(BaseModel):
    """Verification findings for one extracted item."""

    model_config = ConfigDict(extra="forbid", frozen=True)

    item_index: Annotated[StrictInt, Field(ge=0)]
    outcome: VerificationOutcome
    status_check: StatusCheck
    reason: StrictStr = Field(min_length=1)
    evidence: tuple[EvidenceReference, ...] = ()

    @model_validator(mode="after")
    def validate_reason(self) -> "ItemVerification":
        if not self.reason.strip():
            raise ValueError("Verification reason must not be blank.")

        return self


class PotentialOmission(BaseModel):
    """A possible clinical mention missing from the extraction."""

    model_config = ConfigDict(extra="forbid", frozen=True)

    category: EntityCategory
    entity: StrictStr = Field(min_length=1)
    evidence: EvidenceReference
    reason: StrictStr = Field(min_length=1)

    @model_validator(mode="after")
    def validate_text(self) -> "PotentialOmission":
        if not self.entity.strip():
            raise ValueError("Omission entity must not be blank.")

        if not self.reason.strip():
            raise ValueError("Omission reason must not be blank.")

        return self


class VerificationResult(BaseModel):
    """Structured response expected from a future verification pass."""

    model_config = ConfigDict(extra="forbid", frozen=True)

    item_checks: tuple[ItemVerification, ...] = ()
    potential_omissions: tuple[PotentialOmission, ...] = ()
    needs_review: StrictBool
    review_reasons: tuple[StrictStr, ...] = ()

    @model_validator(mode="after")
    def validate_review_decision(self) -> "VerificationResult":
        """Prevent flagged findings from being silently accepted."""

        if any(not reason.strip() for reason in self.review_reasons):
            raise ValueError("Review reasons must not be blank.")

        unresolved_item = any(
            check.outcome != "supported"
            or check.status_check in {"incorrect", "uncertain"}
            for check in self.item_checks
        )

        review_required = (
            unresolved_item or bool(self.potential_omissions)
        )

        if self.needs_review and not self.review_reasons:
            raise ValueError(
                "A result needing review must include review reasons."
            )

        if not self.needs_review and (
            review_required or self.review_reasons
        ):
            raise ValueError(
                "Unresolved findings must be marked for human review."
            )

        return self


class VerificationOutputError(ValueError):
    """Raised when a verifier response fails contract validation."""

    def __init__(
        self,
        code: str,
        message: str,
        *,
        detail_code: str | None = None,
    ) -> None:
        super().__init__(message)
        self.code = code
        self.detail_code = detail_code


def validate_verification_output(
    payload: object,
    extraction: ExtractionResult,
    original_note: str,
) -> VerificationResult:
    """Validate verifier output against an extraction and its source note.

    Checks:
    - The original extraction's evidence spans are valid.
    - Every extracted item is checked exactly once.
    - Status checks match the entity category.
    - Evidence references match the exact original-note substring.
    - Unresolved findings cannot be marked as requiring no review.

    This validates structure and source references, not semantic correctness.
    """
    if not isinstance(original_note, str):
        raise TypeError("original_note must be a string.")

    if not isinstance(extraction, ExtractionResult):
        raise TypeError("extraction must be an ExtractionResult.")

    try:
        validate_evidence_spans(extraction, original_note)
    except (ValueError, TypeError) as exc:
        raise VerificationOutputError(
            "input_extraction_invalid",
            "The input extraction has invalid source evidence.",
        ) from exc

    try:
        result = VerificationResult.model_validate(payload)
    except ValidationError as exc:
        raise VerificationOutputError(
            "verification_schema_failed",
            "Verification output failed schema validation.",
        ) from exc

    # Every extracted item must be checked exactly once.
    indices = [check.item_index for check in result.item_checks]
    expected_indices = set(range(len(extraction.items)))

    if (
        len(indices) != len(set(indices))
        or set(indices) != expected_indices
    ):
        raise VerificationOutputError(
            "verification_coverage_failed",
            "Verification must check every extracted item exactly once.",
        )

    # Only diagnoses and medications have status fields in the contract.
    status_categories = {"diagnosis", "medication"}

    for check in result.item_checks:
        item = extraction.items[check.item_index]
        status_applies = item.category in status_categories

        if status_applies and check.status_check == "not_applicable":
            raise VerificationOutputError(
                "verification_status_check_invalid",
                "Diagnosis and medication status must be checked.",
            )

        if not status_applies and check.status_check != "not_applicable":
            raise VerificationOutputError(
                "verification_status_check_invalid",
                "Status checks are not applicable to this category.",
            )

        status_context_error = validate_item_status_context(
            item,
            original_note,
        )
        if status_context_error is not None and check.status_check == "correct":
            raise VerificationOutputError(
                "verification_status_check_invalid",
                "Verification marked a source status conflict as correct.",
                detail_code="status_context_mismatch",
            )

        if (
            check.outcome in {"supported", "contradicted"}
            and not check.evidence
        ):
            raise VerificationOutputError(
                "verification_evidence_failed",
                "Supported or contradicted findings require evidence.",
                detail_code="required_evidence_missing",
            )
        if check.evidence and not entity_evidence_is_grounded(
            item.entity,
            " ".join(
                reference.evidence_text
                for reference in check.evidence
            ),
        ):
            raise VerificationOutputError(
                "verification_evidence_failed",
                "Verification evidence does not support the extracted entity.",
                detail_code="evidence_entity_mismatch",
            )

    references = [
        reference
        for check in result.item_checks
        for reference in check.evidence
    ]
    references.extend(
        omission.evidence
        for omission in result.potential_omissions
    )

    for reference in references:
        if reference.end_offset > len(original_note):
            raise VerificationOutputError(
                "verification_evidence_failed",
                "A verification evidence span exceeds the original note.",
                detail_code="evidence_offset_out_of_bounds",
            )

        actual_text = original_note[
            reference.start_offset:reference.end_offset
        ]

        if actual_text != reference.evidence_text:
            raise VerificationOutputError(
                "verification_evidence_failed",
                "A verification evidence span does not match the original note.",
                detail_code="evidence_text_offset_mismatch",
            )

    for omission in result.potential_omissions:
        if not entity_evidence_is_grounded(
            omission.entity,
            omission.evidence.evidence_text,
        ):
            raise VerificationOutputError(
                "verification_evidence_failed",
                "Omission evidence does not support the omitted entity.",
                detail_code="evidence_entity_mismatch",
            )

    return result
